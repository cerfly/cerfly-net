How I Built This Site — No Frameworks, No Excuses

September 2026 · Web Development

When I decided to build a personal website, I could have used any template or framework. Instead, I chose to type every line of HTML, CSS, and JavaScript myself — with help from opencode, an AI coding assistant that lives in my terminal next to my code.

opencode isn't a magic button that writes the site for me. It's more like a patient tutor sitting beside me: I ask questions, it suggests code and explains why, I read every line before keeping it. The result is the same as hand-writing the site, but the learning curve is gentler and the errors are easier to fix.

Should everyone learn this way? If you're new, having an expert on call speeds things up a lot — as long as you don't let it replace understanding. I read the docs, break things on purpose, and keep every line that goes on this page explained and mine.

This site started as four pages and a stylesheet. It grew a dark/light theme, a skills section, and now lives on Cloudflare Pages. Every deploy is a git push. That's it. Simple, boring, and completely mine.

How I Put This Site Live: GitHub + Cloudflare Pages

September 2026 · Deployment

After building this site locally, I needed to put it on the internet — and I wanted the way I update it to be boring and repeatable. One git push, site updates. No ftp, no file managers, no drama. Here's the exact path I took, including the bumps.

Step 1 — Make GitHub trust my machine. I created an SSH key and added its public half under GitHub Settings → SSH and GPG keys → New SSH key, with the type set to Authentication key. (Missing that type means GitHub silently refuses your key.) I verified with ssh -T git@github.com until I saw my username.

Step 2 — Create a repo and push. I made an empty public repo called cerfly-net, ran git init -b main, committed, added the remote, and pushed with git push -u origin main. Empty is important — a repo pre-seeded with a README means a merge dance I didn't want.

Step 3 — Connect Cloudflare Pages. In the Cloudflare dashboard: Workers & Pages → Create application → connect a repository → picked the repo. Two settings matter for a static site: build command left blank, and build output directory set to /. Hit Save and Deploy, and I had a .pages.dev URL.

Step 4 — Point my domain at it. My domain was already on Cloudflare's DNS, so in the Pages project I went to Custom domains and added cerfly.net. It refused at first because an old CNAME (cerfly.net → cerfly.github.io from years ago) was squatting on the name. One record deleted in DNS settings, retried, activate. Done.

The payoff. Every deploy from now on is git commit & git push. Cloudflare rebuilds, redeploys, and hands back a 200. For a personal site that's the whole loop — and it cost me nothing but patience with one stubborn CNAME record.
